### How the candidate-pool (scope) system works today — extend this for new scopes

**Frontend (scope selection → concrete source_type):**
- `web/src/features/strategies/scopeCatalog.ts` — `SCOPE_CARD_DEFS: ScopeCardDef[]`. Each card has
  `{id, category:'crypto'|'stock', label, description, provider:'free'|'paid', source_type,
  variant?, defaultLimit}`. `toScopeUnit(def, limit)` builds a `ScopeUnit`.
  - The FREE cards today are the 3 `hyper_rank` cards (gainers/losers/volume) via the
    `freeHyperRank` helper. The "paid" cards (`vergex`, `ai500`, `nofxos_oi`, `nofxos_netflow`,
    `nofxos_price`) actually route through free vergex.trade endpoints too, but are still labeled
    PAID. New free sources should be added as `provider:'free'` cards.
- `web/src/features/strategies/ScopeStepPage.tsx` — renders the cards (single-select radio),
  prefills on edit via `matchConcreteScope` (translates a persisted `coin_source.source_type` back
  to a scope card). To prefill a new source_type, `matchConcreteScope` must recognize it.
- `web/src/features/strategies/strategyFactory.ts` — `buildCoinSource(unit)` maps a `ScopeUnit` to
  a concrete `CoinSourceConfig`. **ADD A NEW BRANCH** for each new source_type (mirror the
  `hyper_rank` / `ai500` / `oi_top` / `netflow_*` / `price_*` / `vergex_signal` branches). It must
  set the corresponding `use_*` flag + limit, `source_type`, and NOT emit `custom`/`scope_mode`.
- `web/src/types/strategy.ts` — `CoinSourceConfig.source_type` union (currently:
  `static|ai500|oi_top|oi_low|netflow_top|netflow_low|price_top|price_low|hyper_all|hyper_main|
  hyper_rank|vergex_signal` — `custom` was removed last session). **Add your new source_type
  string(s)**. Also `ScopeUnit.source_type` union + `ScopeVariant` if you add variant-qualified cards.

**Backend (source_type → candidate pool):**
- `kernel/engine.go` `GetCandidateCoins()` — a `switch coinSource.SourceType` with a `case` per
  source (static, ai500, oi_top, oi_low, netflow_*, price_*, hyper_all, hyper_main, hyper_rank,
  vergex_signal, mixed, default→error). **ADD a `case` for each new source_type** that calls a
  new getter returning `[]CandidateCoin`, then `filterExcludedCoins`.
- Single-source getters live in `kernel/engine.go` (e.g. `getAI500Coins`, `getOITopCoins`,
  `getNetflowTopCoins`, `getPriceTopCoins`, `getHyperRankCoins`, `getVergexSignalCoins`). Each uses
  `e.trending` (`*nofxos.FreeTrendingClient`) or `e.freeClient` (`*vergex.Client`) or
  Hyperliquid-native data. New scopes should reuse these free clients.
- `provider/nofxos/free.go` — `FreeTrendingClient` (vergex.trade `/trending-crypto`, tabs
  `oi`/`net_flow`/`price`, plus `/trending-category` for ai500). **If a new scope needs a new
  tab/endpoint, add the fetch method here.**
- `store/strategy.go` `CoinSourceConfig` — has `source_type` + the `use_*`/`*_limit` fields. **Add
  new `use_*`/`*_limit` fields if your new source needs a new toggle/limit.** Also `normalizeCoinSourceType`
  / `inferCoinSourceType` and `ClampLimits` (switch at ~line 1685) may need new cases + token
  estimation handling. The frontend type must match these backend field names exactly.

**How a single selected scope is used at runtime:**
1. `ScopeStepPage` → user picks one card → `buildCoinSource(unit)` emits a concrete `source_type`
   + `use_*`/limit into `ai_config.coin_source`.
2. Strategy saved (config JSON). Trader's `StrategyEngine` reads `config.CoinSource`.
3. Each cycle `GetCandidateCoins()` resolves the pool. If 0 candidates → "No candidate coins
   available, cycle skipped". So a new scope MUST return a non-empty pool to be useful.

## Constraints to respect
- `go vet ./...` + `gofmt` clean; frontend `npx tsc --noEmit && npm run build && npm test` pass.
- English-only UI strings. Backend uses `SafeError`/`SafeInternalError`/`SanitizeError`.

- `store.*` is the only DB access layer. All timestamps UTC.
- Backend `CoinSourceConfig` and `IndicatorConfig` field names must match the frontend TS types exactly

  omitted from the prompt (non-mutating shallow copy).
